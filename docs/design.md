# Serendipity Engine · 奇遇记引擎

## 图谱漫游：让双链真正跑起来（Graph Roaming: Making Bidirectional Links Come Alive）

> 定位：本地 CLI + Web 工具，查询驱动的图谱漫游（pull）——用户查询某个点，自动得到一批经过筛选、排序、可解释的相关节点。这是渐进阅读（push，调度）之外的另一种东西：**在笔记中漫游**。
> 性质：独立设计研究（本地 CLI + Web 工具，不绑死任何笔记软件）。与 dsh-mneme 图谱增强同哲学、不同领域——mneme 管 agent 记忆，本文管**人的笔记导航**。
> 相关文档：战略定位 [`positioning.md`](positioning.md) · 总路线图 [`roadmap.md`](roadmap.md) · 后端积压 [`backend-backlog.md`](backend-backlog.md) · 前端计划 [`frontend.md`](frontend.md) · 组件架构 [`architecture/`](architecture/) · AI 用法 [`SKILL.md`](SKILL.md)。

## 一、核心命题

> **图的价值 = 结构 × 激活。任何一个为零，图就是死的。**

笔记软件有结构（双链）、没有激活（运行时信号），所以它的图谱是静态装饰。本文要做的事：给笔记双链装上激活引擎，让链接网络对查询作出响应。

## 二、概念定位：拉（pull），不是推（push）

| 维度 | 渐进阅读（push） | 图谱漫游（pull，本文） |
|---|---|---|
| 驱动 | 时间 / 进度调度 | 查询 / 意图 |
| 输出 | 下一步该读的 1-3 篇 | **一批筛选后的相关节点** |
| 目的 | 管理学习流程 | 知识导航与探索（serendipity） |

本文做的是**增量披露的图谱版本**：让双链拓扑决定导航顺序，时间只作修正（heat）。它不碰复习调度。

## 三、现状诊断：双链为什么是死的

| 工具 | 有什么 | 缺什么 |
|---|---|---|
| Obsidian Local Graph | 显示邻居节点 | 不筛选、不排序、不解释 |
| Obsidian Backlinks | 直接入链列表 | 只到 1-hop、无激活、无优先 |
| Roam / Logseq | linked references | 无拓扑驱动的推荐/漫游 |

导航需要四个能力，现有工具全缺：**筛选**（多跳+剪枝的簇）、**排序**（分数+解释）、**可解释**（激活路径）、**可干预**（认可/忽略→反馈）。

## 四、核心机制

### 4.1 查询 → 激活扩散 → 节点簇

```
用户查询点（笔记 / 词 / 标签）
  → 锚定（精确名 / 标签 / 全文命中，起点是集合非单点）
  → 双链激活扩散（λ 衰减 + θ 剪枝，多跳；关联边对称，传递边沿"来源→拓展"方向传播）
  → 四维打分融合
  → 输出 top-10~20 节点簇（带分数 + 激活路径）
  → 用户消费（读 / 跳过 / 深入）→ touch → 反馈
  → 下次查询更强（正循环，衰减约束）
```

### 4.2 四维打分

| 维度 | 信号 | 来源 | 语义 |
|---|---|---|---|
| 结构分 | **查询锚定的 PPR**（以查询点为种子） | 图拓扑 | 在以当前查询为背景时，这是枢纽还是跨主题跳板 |
| 激活分 | 从查询点出发的扩散值 | 激活扩散（λ 衰减 + θ 剪枝） | 离我此刻的思维有多近 |
| 时效分 | heat / recency | 访问记录 + 分层衰减 | 现在还重不重要 |
| 依赖分 | 引用方向推断 | 边语义（关联/传递） | 我该先读它吗 |

融合公式：`分数 = α·结构 + β·激活 + γ·时效 + δ·依赖`。每维先归一化再融合。δ 默认 0（依赖分独立为"路径排序"输出，不进 serendipity 排名）；γ（时效）默认 0（v1 不引入 heat，理由见 §7.2）。

### 4.3 边语义：关联 vs 传递

| | 关联（Association） | 传递（Transmission） |
|---|---|---|
| 本质 | 对称、静态——"A 让我想起 B" | 非对称、有方向——"A 是 B 的前置" |
| 图论特征 | 互链、双向 | 单向、入度/出度不对称 |
| 对应打分 | 结构分（无向） | 依赖分（有向） |

**关键约束：用户自己也说不清链接语义 → 不能要求标注，用推断替代。**
- **冷启动（纯统计，零 LLM）**：互链→关联；全库路径顺序一致性→传递；单向链接噪声太大，不构成方向证据。
- **热启动（行为反馈）**：只用**有效转移**（目标节点停留 ≥ 5s 且无 3s 内回跳）。防自指污染：只用停留时长和展开动作做信号，点击顺序本身不作为信号。
- **推断统计量**：每条边存两个有向计数 (A→B, B→A)，EWMA 平滑；方向分 `D=(N→−N←)/(N→+N←)∈[−1,+1]`；总转移 ≥ 3 次才更新。
- **扩散分化**：关联边无向对称扩散；传递边有向扩散（沿"来源→拓展"方向传播更快）。参数初值：停留阈值 5s / 回跳窗口 3s / 置信门槛 3 次 / EWMA 半衰期 7 天。

### 4.4 输出形态：给区域，不给单点

输出一批（10-20 条），每条带分数和激活路径说明。排序在归一化融合后**按跳数配额混合取 top-N**（默认 1:2:3-hop = 0.5/0.3/0.2）——这是 serendipity 的主旋钮（λ/θ 只决定可及性）。度 ≥ 半数节点的目录页（index）与锚点种子（0-hop）从结果中排除。

### 4.5 反馈闭环

- **读 = 隐式认可** → 边权 ↑（被读过的路径加粗）
- **跳过多次** → 异常介入三选一：暂时不想看 / 内容无关 / 链接标错了
- **人工旋钮**（用户显式优先级）防隐式信号的正反馈循环
- **v1 不做边权演化**：touch 只记录不演化，"点击→边权变→结果变→再点击"的跑飞在源头切断

## 五、与 dsh mneme 的关系：同引擎，双界面

笔记漫游与 dsh mneme 图谱增强是同一个激活引擎思路的两个实例化——数据源和消费者不同，机制同构。

| 环节 | dsh mneme（agent 侧） | 图谱漫游（人侧） |
|---|---|---|
| 查询 | 会话 query | 用户查询点 |
| 锚定 | matchEntities | 节点名 / 标签 / 全文命中 |
| 扩散 | entity_relations 多跳 | 双链 links_to 多跳 |
| 融合 | 语义分 × tagBoost × (1+激活) | 结构 × 激活 × 时效 × 依赖 |
| 输出 | 注入 system prompt | 可视化节点簇 |

**两处本质差异**：① 冷启动相反——笔记双链天然带权（引用关系写入即确定，结构分/依赖分第一天就存在）；② 消费者不同——人不是 LLM，输出从"注入文本"变"可视化面板"。

**双消费者设计**：同一份 `(节点, 分数, 激活路径)` 产出开两个通道——
- **通道 A（人）**：渲染为导航面板
- **通道 B（外部 AI）**：外部 AI/agent 经**只读 MCP 工具**消费同一份产出（见 [`SKILL.md`](SKILL.md) 与 [`architecture/07-mcp.md`](architecture/07-mcp.md)）。引擎零 AI 依赖，AI 是外部消费者，不是引擎内置组件。

## 六、对标：Roaming Mode Incremental Reading（思源笔记插件）

它是现存最接近本构想的项目：TF-IDF 余弦相似度 + 人工指标权重 + 轮盘赌随机。对比：

| 维度 | Roaming Mode | 图谱漫游（本文） |
|---|---|---|
| 关系信号 | TF-IDF 文本相似度（内容"像不像"） | 双链激活扩散（关系"相不相关"） |
| 锚点 | 最近漫游 + 高频漫游（时间聚合） | 用户查询点 |
| 图谱 / 双链 | 完全缺席 | 核心载体 |

它验证了"渐进阅读第一步值得做成推荐器"需求真实存在；它缺的是图谱（只找像的，找不到相关的）。**该偷的**：用户显式优先级旋钮——人工把"人的意图"放回回路，是 mneme "确认=强反馈信号"的用户侧变体。

## 七、设计细节

### 7.1 参数继承（初值，spike 重测）

| 配置 | 默认 | 说明 |
|---|---|---|
| 衰减因子 λ | 0.6~0.7 | 每跳衰减 |
| 激活阈值 θ | 0.1 | 低于 θ 剪枝 |
| 最大跳数 maxHops | 3 | 深跳是弱关联征兆 |
| 输出规模 | 10-20 条 | 给"区域形状" |
| **跳数配额** | 1:2:3-hop = 0.5/0.3/0.2 | serendipity 机制 |
| 时效权重 γ | 0（默认关闭） | v1 不引入 heat |
| 依赖权重 δ | 0（默认关闭） | 依赖分独立为路径排序 |
| 边初始权重 | 手动 1.0 / 自动 0.3-0.4 | 按来源分级 |

### 7.2 冷启动：双链天然带权

与 mneme 相反，笔记双链写入即确定：结构分（PPR）和依赖分（引用方向）第一天就存在，无需实体抽取、无需等待 touch 积累。v1 的价值定位 = **结构驱动的导航**（PPR + 双链拓扑），"越用越准"的行为演化是后续增益，不作为 v1 卖点。

### 7.3 反馈信号与正反馈风险

无可靠反馈 → 权重退化为"越点越多"的正反馈循环。对策：被动路径（读=隐式认可）+ 异常介入（跳过多次才打扰）+ 人工旋钮。touch 升级为有向转移（记录"从哪来"）——阅读序列成为边语义的强信号。

### 7.4 白盒原则

- 每个推荐节点**必须可解释**：显示激活路径
- 用户可干预：忽略 / 删除链接 / 调优先级，全部走审计留痕
- **源数据权威原则**：索引可重建、源数据不可丢——宁可搜不到，不要搜到坏结果。图 = 真实链接；LLM 生成的二手物会崩塌白盒承诺（见 [`positioning.md`](positioning.md) §六）。

### 7.5 人工旋钮

一维人工可调项（如"兴趣"或"难度"）作为四维打分的修正系数：机器管结构/激活/时效，人管意图。

### 7.6 AI 集成：经 MCP 暴露，引擎零内置 AI

引擎产出确定性、可解释、永远在线、免费的事实（roam / similar / communities / suggest-links / relation / node）。**外部 AI/agent 经只读 MCP 工具消费这份产出**（`SKILL.md`）；插件仅为薄壳（iframe 嵌 Web UI + 连接 + 跳回 + 隐式 touch + digest 导出），**不内置 AI**。

引擎边界（白盒铁律）：引擎 = 算法 + 接口，对外只提供确定性算法结果与只读/写入 REST 契约，**没有任何 AI 代码路径、不调用任何模型**。所有 AI 行为发生在引擎之外，引擎对此无感知。语义研判（补链/推荐理由）不在引擎范围内——这是"纯本地算法、不引入语义层"决策的直接后果。

### 7.7 建库 = 解析（无 AI 补图）

"全库扫"两种含义成本差两个量级：LLM 实体抽取（重，关系是猜的）vs 双链解析（轻，纯文本，关系是用户写的、100% 准）。双链场景没有"建图"步骤，只有"读图"：每次启动全量重扫（秒级），文件变更增量重扫相关文件。mneme 要造图（隐式关系要抽），笔记图是白送的（显式关系读就行）。

### 7.8 技术栈与产品形态：核心服务 + 三入口

**产品形态**：本地 CLI + 人工可用的 Web 应用 = 同一个本地核心服务，三个入口：

| 入口 | 用途 | 协议 |
|---|---|---|
| CLI | 脚本 / 终端漫游 / 测试 | 子命令 |
| Web UI | 可视化节点簇 / 拖拽调权重 | REST / JSON |
| AI | 暴露给 agent | 只读 MCP server |

**技术栈：纯 Go，零 AI 依赖，单二进制。** 双链解析 / 图引擎 / 边权存储 / 四维打分 / 反馈闭环 / CLI / REST / MCP 全部 Go 标准库够用。Go 当核心的理由：单文件分发、秒启动、交叉编译（Windows 开发 / Linux 部署）；网络环境差时"装个 Python 再跑"是劝退，单二进制是硬需求。

**存储：bbolt 嵌入式 KV（v0.1.13 落地）**——四个 bucket（docs/links/touch/renames）一一映射 KV 语义；无迁移（旧 sqlite 直接删，refresh 重建）；增量写（差值 Put/Delete）。详见 [`backend-backlog.md`](backend-backlog.md) §二.1。

**多库**：每库一 DB（`<vault>/.serendipity/db-<hash>.bbolt`）；库手动迁移时图跟着走，但 `.serendipity/` 不进云同步——结构可重建，行为层（边权/heat/转移计数）本地化。跨库漫游 = 高阶功能，后置（内存层合并）。

**启动对账**：内核离线期间笔记增删改 → 启动主动扫描比对（路径+mtime+大小，不做内容解析）→ ① DB 有磁盘无→软删除（valid_until，边权保留）② 磁盘有 DB 无→解析建节点 ③ 两边有 mtime 变→重解析。软删除 = bi-temporal（搬走/换库时边权不丢）。`.serendipity/` 必须排除在对账范围外（防 DB 自触发死循环）。Obsidian 文件名即 ID，改名按内容哈希/路径相似度识别并合并迁移边权。

**配置**：YAML（配置，可注释自文档化）/ JSON（数据，导出/备份/REST/运行时）。载体三级：vault 级 `config.yaml` > 全局 config（`~/.serendipity/`）> 内置默认。

### 7.9 多笔记软件适配：统一图格式 + adapter

Go 核心只认识一种统一图格式（节点+边+标签），每个笔记软件一个 adapter 负责格式翻译。核心零感知，适配器可插拔。

**内核职责边界：Document API = VFS**——`id · 内容 · mtime · 路径` 是内核唯一格式抽象；事件解释在 adapter（路径→节点 ID、文件内容→双链/标签），adapter = 无状态纯解析器。适配更多格式 = 第三层加一个 adapter，内核/存储/图引擎全不动。

**VaultProfile（YAML 画像）**：通用语法（`[[...]]`、frontmatter、H1）代码固定；"语义映射规则"（title/别名/标签键、排除目录、类型推断）抽成可配置层，换库不改 Go 代码。`seren profile-detect <vault>` 自动产出画像骨架。类型字段（spike 落地）：Document 增加 `Type`，实体查询默认从节点簇排除 `structural_types`。OKF（Google Open Knowledge Format）通用格式已落地（v0.1.1）。

**图自洽性原则**：节点粒度 = 原生链接粒度（Obsidian 页面 / 虎鲸页面 / 思源同理）。标题与 ID 分离（title 独立提取，ID 不动）——纯编号文件名不阻塞锚定。

**适配优先级（自用优先）**：Obsidian（v1 唯一，文件解析最便宜）；虎鲸（v1.5，SQLite 直读 + 页面聚合——v0.1.1 实测节点 4919→1832，枢纽全为真实标题）；思源预留（不做）。**虎鲸 adapter 结论**：数据全在 `OrcaNote.db`（SQLite，WAL），adapter 走 SQLite 直读（先拷贝再读，绝不锁活库）；`Repo` 表含用户凭据，adapter 与拷贝必须排除——图数据只从 Block/BlockRef/BlockAlias/BlockProperty 派生。

**边界声明**：adapter 接口不锁死数据源类型（日历/邮件都是同一接口的实例），但落地范围钉死在笔记（Obsidian + 虎鲸）。

### 7.10 跨平台与便携性

目标：Win / Linux / Mac 三平台（Go 交叉编译一行命令，单二进制）。不用 Electron；原生壳用 Wails（同语言，不引第二运行时）。

**三个文件系统纪律**：① 路径规范化（双链文件名匹配统一小写归一）② 换行符归一（CRLF/LF）③ 文件监听节流（Windows 大量小文件事件风暴→合并/节流）。**便携性**：库内存相对路径，配置只存 vault 根——笔记库跨机手动拷贝图不烂（结构层）。

## 八、诚实的评估

### 8.1 值钱的场景

1. **结构算法桥不动的长尾关系**：语义不相似但关系明确（跨项目工具偏好、项目换方案的失效）——激活扩散能桥，TF-IDF/向量未必
2. **可解释 / 可干预的导航**：用户想"知道为什么"或"主动改一下"——黑盒推荐做不到
3. **探索性发现（serendipity）**：漫游特有的价值——"我没想到但确实相关"的惊喜节点，检索和调度都不测这个

### 8.2 三个难点

1. **反馈信号弱**——无可靠反馈，权重演化和推荐质量都悬空
2. **"程序化经验"不是推荐器能交付的**——图谱最大贡献是按依赖顺序披露
3. **heat 不引入核心路径（γ 默认 0）**——笔记是用户精选（无需自动降级）、查询驱动（激活分已承担"离当前意图多近"）、节点簇输出预算宽松；边权衰减会让旧知识被压死。保留两个可选扩展点：锚定消歧、漂移检测

### 8.3 开放问题

1. Web UI 形态（本地静态页 + REST，还是内嵌服务端渲染）
2. "读"的反馈信号：接受弱信号还是强制显式标记？
3. 与现有 SRS（Anki 等）的关系：**分立**（本文只管拓扑驱动的导航，复习交给现有工具）
4. 四维权重 αβγδ：v1 只有一组全局默认，场景级配置后置

## 九、验证实验（MVP）

> **核心命题**："同一个激活引擎，从 entity_relations 换到笔记双链，输出给人看，能否产生'我没想到但确实相关'的节点？"

- **数据**：个人笔记库（Obsidian）解析双链成图
- **查询集**：10 个实际关心的主题
- **输出**：每主题 top-10 节点 + 激活路径
- **判定（定性）**：图谱版稳定产出"我没想到但确实相关"的节点，且可解释/可干预两条成立 → 方向成立。不设数字门槛（n=1 下任何硬门槛都是伪严谨），逐条记录惊喜节点/可解释性/干预效果。对照基线（TF-IDF 管道）后置。
